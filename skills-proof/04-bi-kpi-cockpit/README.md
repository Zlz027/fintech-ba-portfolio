# 金融科技BA核心指标看板（BI）

> **一句话结论**：把四个金融 AI 项目的分散结果整合成一张"管理层驾驶舱"——左侧看风控定价，右侧看欺诈成本，顶部看留存 ROI，底部看现金流缺口。

## 证明什么技能

- 面向管理层的指标口径设计与"一屏决策"布局

## 看板说明

**数据说明：本项目数据为固定随机种子生成的模拟数据（生成脚本见 `scripts/build_bi_tables.py`），仅用于演示分析方法与工具链，不涉及任何真实业务、客户或敏感信息。**

- **指标卡**：信用风险 CV AUC 0.863、客户挽留 ROI 2.62x、欺诈检测节省成本 62.5%、月度经营融资缺口 ¥2,920万，一眼定调。
- **五联图**：通过率-坏账率-利润率曲线、成本-阈值曲线、优先挽留散点、13 周现金流预测、三情景利润。
- **筛选器**：风险分层与合同类型（作用于散点图）、情景（作用于三情景利润图）。
- **口径备注**：现金流图为 Base 情景口径（源数据仅含 Base 路径）；P3 成本曲线为对数轴。

## 面试话术（30 秒版）
> "这个看板解决的是'一屏决策'问题。四个项目各自跑出了模型和测算结果，但 CFO 没有时间翻四份报告。我把核心指标抽成四个指标卡——AUC、ROI、节省成本、融资缺口——再用曲线、散点和 13 周现金流预测展示趋势和风险。比如 Bear 情景一切换，年利润 -179.4 万的亏损一目了然；13 周现金流第 6 周就击穿了 ¥3,000 万安全线，融资缺口 ¥2,920 万——这就是 FP&A 每天要回答的问题。"

## 面试话术（2 分钟版）
> **（先数字）**"看板顶部四个数字分别对应四个项目：P1 风控定价模型 CV AUC 0.863、P2 挽留 ROI 2.62x、P3 欺诈检测节省成本 62.5%、P4 的融资缺口 ¥2,920 万。
> **（再口径）**"每个指标我都注明了计算口径：节省成本 = 不拦截成本 ¥11,479 − 成本最优阈值成本 ¥4,309；ROI 取自挽留成功率 30% 的基准情景；融资缺口 = ¥3,000 万缓冲线 − 第 13 周见底 ¥80 万。每个数字都能在对应项目 README 里复核。
> **（最后决策）**"最有决策价值的是 13 周现金流预测：虚线是 ¥3,000 万安全缓冲线，第 6 周击穿、第 13 周见底 ¥80 万，80% 悲观下界 -¥4,434 万——直接触发融资谈判（建议循环授信 ¥7,500 万）。右侧散点图按流失概率和 LTV 分层，告诉运营优先挽留谁。"

## 文件说明
- `dashboard_link.md`：直达链接与更新方式
- `data/`：四个 CSV 数据源（指标卡宽表 / 曲线长表 / 客户明细 / 三情景利润）
- `images/`：看板截图
- `scripts/build_bi_tables.py`：从 P1–P4 outputs 生成 CSV 的脚本（含交叉验证）

## 复现方式

> 仓库中不包含 Tableau 工作簿文件（.twb/.twbx 为二进制文件，已在 .gitignore 中排除，不适合随代码做版本管理）。完整复现按以下三步走：

1. **生成数据**。在仓库根目录运行：

   ```bash
   python3 skills-proof/04-bi-dashboard/scripts/build_bi_tables.py --out skills-proof/04-bi-dashboard/data
   ```

   输出与仓库中 `skills-proof/04-bi-dashboard/data/` 下的 4 个 CSV 一致；唯一预期差异是「数据生成日期」列会变成运行当天（如需与仓库版本完全一致，用 `BUILD_DATE=<仓库版本日期> python3 ...` 固定，如 `BUILD_DATE=2026-10-19`）。

2. **重建看板**。按交付文档第四章《搭建指南》，在 Tableau Public 桌面版中新建工作簿，连接上述 4 个 CSV，按步骤搭建工作表和仪表板。

3. **核对成品（可选）**。在 Tableau Public 看板页面下载我发布时使用的 .twbx 工作簿（下载方法见交付文档 5.1 节），在 Tableau Public 桌面版中打开，逐项核对数据连接与图表设置。
