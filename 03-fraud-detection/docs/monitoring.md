# 监控方案：交易欺诈检测与成本敏感拦截

> **用途**：回答"模型上线后怎么盯"——监控什么、告警线在哪、越线后做什么。
> **特点**：欺诈监控看**四个数**（PSI / 阈值精确率 / Top-500 精确率 / 每千笔成本），任一越线触发重训或阈值重标。

## 1. 监控对象与频率

| 层级 | 指标 | 频率 | 责任方 |
|---|---|---|---|
| **数据层** | V1-V28 特征口径一致性、Amount/Time 异常 | 日（T+0/T+1） | 特征平台 |
| **模型层** | 评分 PSI、阈值精确率、Top-500 精确率 | 日 / 周 | 模型团队 |
| **业务层** | 拦截量、召回、误杀客诉量、复核队列长度 | 日 | 反欺诈运营 |
| **财务层** | 每千笔期望成本、实际欺诈损失 | 月 | 反欺诈 × 财务 |

## 2. 告警线（本项目四指标）

| 指标 | 当前值 | 告警线 | 动作 |
|---|---|---|---|
| **评分 PSI** | 0.0014 | **> 0.25** | 触发重训评审工单 |
| **阈值精确率** | 0.9032 | **< 0.15** | 复核阈值与成本矩阵 |
| **Top-500 精确率** | 0.128 | **< 0.10** | 复核模型排序力 |
| **每千笔期望成本** | ¥75.7 | **环比 +50%** | 复核成本矩阵与客群结构 |

## 3. 越线后的动作（Runbook）

| 触发 | 动作 | 时限 |
|---|---|---|
| 评分 PSI > 0.25 | 定位漂移特征 → 检查上游特征管道 → 评估重训 | 5 个工作日 |
| 阈值精确率 < 0.15 | 复核阈值配置；重跑成本矩阵下的最优阈值 | 3 个工作日 |
| Top-500 精确率 < 0.10 | 检查模型排序力衰减；评估新旧模型对比 | 10 个工作日 |
| 每千笔成本环比 +50% | 复核成本矩阵假设（fp_cost/miss_fixed）与实际损失 | 5 个工作日 |
| 误杀客诉突增 | 抽检拦截样本；必要时临时上调阈值（降低误杀） | 当日 |

## 4. 重训与重标触发条件

**重训**（模型层面）：
1. 评分 PSI > 0.25；
2. Top-500 精确率连续 2 周 < 0.10；
3. 欺诈形态出现新变种（规则召回显著衰减）。

**阈值重标**（成本矩阵层面，不改模型）：
1. 每千笔期望成本环比 +50%；
2. 财务部季度成本矩阵校准（fp_cost / miss_fixed 修订）；
3. 误杀成本假设变动（如客诉率上升 → fp_cost 上调 → 阈值上移）。

> **关键区分**：模型衰减靠"重训"，成本结构变化靠"阈值重标"——两者混为一谈会导致过度重训。

## 5. 人工抽检与回流（成本矩阵校准）

- **抽检比例**：拦截样本抽检 5%，人工标注真伪；
- **回流用途**：用抽检结果校准 fp_cost（误杀的真实客诉成本）与 miss_fixed（调查成本）；
- **A/B 实验**：新旧阈值/模型并行 2 周，对比每千笔期望成本；
- **闭环**：校准结果写入成本矩阵 → 重算最优阈值 → 上线。

## 6. 审计留痕（合规要求）

- **阈值标定过程**：每次最优阈值计算保存成本矩阵版本、样本窗口、阈值结果；
- **拦截决策**：单笔拦截的评分、规则命中、理由码全部落库，保存 ≥ 5 年（客户告知义务）；
- **公平性审计**：定期检查是否对特定客群系统性误杀（不得因受保护属性差别对待）；
- **模型快照**：训练数据版本、特征清单、超参数、随机种子。

## 7. 监控数据流

```
交易特征平台（准实时）
   ├─ 欺诈评分（P99 < 50ms）
   ├─ sql/metrics.sql → 日指标表（PSI/精确率/Top-K/每千笔成本）
   └─ 规则引擎（前置实时拦截）→ 复核队列
        └─ 四指标越线 → Runbook 工单 → 重训 / 阈值重标
             └─ 人工抽检 5% → 校准成本矩阵 → 闭环
```
